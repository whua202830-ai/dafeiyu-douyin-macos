# 1.4.5 本地候选验收

日期：2026-10-24。本文保留当时的内部候选验收和旧操作方式，不作为当前使用指南。后续改动已纳入 1.4.5，当前操作见[本版说明](../features-1.4.5.md)，最终公开状态见[发布记录](../publication.md)。

## 问题与改动

本轮依据 GitHub [#1](https://github.com/LockyBee/dsh-douyin-agent/issues/1)、[#2](https://github.com/LockyBee/dsh-douyin-agent/issues/2)、[#3](https://github.com/LockyBee/dsh-douyin-agent/issues/3)及用户要求适配。

- 关注面板不存在或被浮层遮挡时，返回“关系未核实”和已有会话，不伪造已关注。本人可核对强身份后显式许可。旧昵称、头像生成的身份与新稳定身份不同时，需要在界面重新勾选保存。
- 个人与群聊共用最多50项许可名单，未知类型不可授权。群聊仅在被 @ 或出现设定昵称时回复；普通群消息不调用模型。续火花只用于个人。
- 2秒轮询加无正文页面通知唤醒。读取、模型生成后和最终发送前复核保存的身份绑定；发送未确认仍暂停，不自动重试。
- 新评论区先激活输入框，识别实际 DraftEditor、零宽占位及无标签箭头控件。固定控件几何不匹配时保留草稿；草稿清空不视为发布成功。
- 非搜索决策容忍额外短 query；直播预览最多连续跳过3张，换片结果不明时以实际作品ID核对。
- 共用发送锁新建但尚未写完的空文件可在短暂有界等待内完成写入；不删除、抢占或重置锁。损坏或过期记录仍拒绝发送。

## 实机证据范围

仅使用专用 Edge profile 和已核对的CDP归属，不接触个人浏览器。

两位既有许可个人会话均取得唯一的渲染行身份哈希，其中一位另与官方公开个人资料入口比对一致。只读取限定行的身份字段，不执行 getter，不读取应用全局状态或凭据。

用户明确授权这两位联系人用于外发测试。前两次文字尝试均在点击前被拦下。实机定位到输入框扩高移走旧消息前缀、按钮滚动补载旧历史、后台RAF节流，以及受控编辑器恢复合成 input 清掉的草稿。修复后，第三次实测向两位联系人各发送一条明确标记的测试消息，均取得对应的新发出消息ID并确认，没有重复点击。

消息窗口变化只在原最新锚点仍在、全部重叠内容一致、新补载部分有可靠旧历史分类时接受；任何新增尾部、指纹改变、重排、丢锚点仍拒绝。后台发送使用三次实际几何稳定与命中核对，再发出一次可信鼠标输入；不仿真焦点或可见性，不强行点击。候选新消息先处于pending、随后确认时保留同一候选ID，历史补载不能充当成功回执。

上述单次文字测试只验证发送链路。随后用户从原许可账号发来新消息，北京时间17:05:19收到、17:05:21确认自动回复送达，覆盖真实收信、模型生成与发送回读。群聊触发、调度、生成取消和防重复由合成测试单独覆盖，不能以个人会话的成功替代群聊实测。

视频卡片同样实测：首轮在旧trial检查阶段超时，未点击；下一轮在准备收件人时因瞬时身份未匹配而拒绝，后续连续三次只读快照与原许可绑定一致，未据此放宽生产检查。最终向其中一位许可联系人分享一条已实际查看的猫咪作品，取得对应作品的新发出官方卡片及消息ID，`confirmed=true`、`deliveryUncertain=false`。没有改发文字链接、重复点击或调用模型。

卡片测试使用隔离目录内的3分钟测试时钟与许可快照，发送协调器仍使用实际共用锁；没有改写原观看时段、预算、Key、人格或许可名单。结束后暂停视频。两位好友各一条测试文字、其中一位一张作品卡片的成功凭据进入本机共同发出账本。

本机没有可用于本轮验收的许可群聊，群列表、触发过滤、类型变化阻断以合成测试覆盖。公开评论没有真人发布授权，本轮只检查实际控件，不发布测试评论。

## 表情、图片与语音

补齐行内原生表情名称、未命名表情的单消息截图，以及普通图片就绪检查。语音只读取指定许可会话中该条已渲染消息的资源字段，限制平台HTTPS来源、下载时间、体积、文件头与消息身份，不点播、不采集麦克风或系统声音。音频仅交给用户已选择的本地 Whisper，临时文件用后释放。

用户提供了独立表情、普通图片和一条空语音。实机采到两张精确消息图片，语音资源为43934字节的AAC/MP4，消息标注3.825秒，解码音轨约3.6秒。本地转写未识别到对白，用户确认这条语音没有说话。有效音轨的无对白结果单独返回 `no-speech`，不冒充转写成功，也不因此暂停后续聊天。损坏结果、下载或转写故障、取消、身份变化仍拒绝发送。

北京时间18:46对这三条既有测试样本进行一次明确授权的联调：单消息采集 → 当前模型 → 共同发送锁 → 消息与许可复核 → 单次发送回读，取得新发出消息ID，`confirmed=true`、`deliveryUncertain=false`，正文没有固定回复前缀。它属于既有样本联调，未改消息水位、未伪造新到达，不能把这一次写成新消息通知的自动触发验收。实际临时采集目录另经回读为空。

真实本地Whisper识别既有SAPI合成语音WAV与无容器时长WebM的两项测试通过，均使用缓存模型、禁止云请求。实际抖音中的有声语音准确性尚未实测；本次空语音不能作为该项证据。MiMo、MiniMax仍没有真实云联调。

## 本地启动与设置草稿

截图中的“白名单联系人必须已有关注关系与非群聊核对记录”逐字来自旧1.4.4软件。它读取了1.4.5的新许可格式而拒绝启动。本机合并启动器已备份并更新候选目录，检查命令选中1.4.5；没有删除名单、伪造关注或放宽身份绑定。公开插件与软件继续独立分发，本机QQ合并入口不进入开源包。

完整回归另发现设置保存竞态：提交保存后继续修改分钟数，迟到的旧保存响应会把新草稿标为干净，下一次轮询将其覆盖。首次包内检查又定位到保存前发出的旧GET回包覆盖已保存值：后端已为不限时长，界面却回到10。插件与软件均增加编辑版本核对，并等待轮询设置与本次保存回执的实际 `policy` 匹配后才解除保护；新增编辑继续保留。延迟POST、延迟旧GET与后续外部更新的确定性测试覆盖两版。
